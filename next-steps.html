当前进度 & 下一步工作

已完成的工作

Agent 基础设施（Phase 1–4 全部完成）
BaseAgent OTAU 循环、ToolRegistry 工具注册、MemorySystem 三层记忆（含 SQLite 后端）、LLMClient 统一调用、协议类型识别、上下文管理、漏洞分析 Agent（多轮迭代 + PromptOptimizer 已接入）、攻击重建引擎、置信度校准、协调调度器、报告生成

接下来要做的

LLM 结构化输出
当前 JSON 解析靠正则剥 markdown 围栏，多轮推理时失败率较高。改为 OpenAI 原生 response_format: json_schema，确保 LLM 输出 100% 合法 JSON。这一步是后续所有分析可靠性的前提。
Slither + AST 双层二次验证（核心工程）
LLM 单独推理假阳性不可靠，需要独立的第二意见来验证 finding 是否真的存在。方案分两层：Slither 跑 70+ 内置 detector，通过手工 mapping 表映射到 21 个 pattern；TypeScript AST 解析器覆盖 Slither 不擅长的 8 个 DeFi 特有模式（闪电贷储备操纵、TWAP 窗口、中心化喂价等）。两者并行跑，结果聚合为"验证通过/反驳/无法判断"，注入报告。目标覆盖 16/21 pattern。
漏洞模式入库（Prisma）
21 个漏洞模式目前是静态 JSON 文件，更新要重新部署。改为 Prisma 数据表 + ingest 脚本，JSON 保留为 single source of truth。
评估 harness
用 33 个历史真实攻击案例跑系统，计算每个 pattern 的精确率/召回率/F1，输出评估表格。验收标准：整体 precision ≥ 30%、recall ≥ 50%。这是论文评估章节的数据来源。
各阶段独立超时
Orchestrator 目前只有一个总超时，调试时看不出哪个阶段慢。拆成每个 stage 独立 budget，超时报清楚是哪个阶段卡住了。

时间允许时追加

置信度收敛自动停止
简单合约不用跑满 5 轮迭代——如果连续两轮置信度差值 < 0.05，自动结束，节省 token。
攻击重建按具体模式区分叙事
当前按 6 大类（预言机/流动性/排序/权限/计算/组合性）写攻击叙事，同类下不同模式报告几乎一样。改为 21 个独立模板。
攻击成本用链上数据计算
用 Etherscan gas 价格 + CoinGecko ETH 价格 + Aave 闪电贷费率算出具体美元区间，替代 LLM 推断的 "low/medium"。
分析 API 改用 SSE 推送
当前前端用轮询读 tasks.json，改为 SSE（EventSource）实时推送分析进度，并发审计互不干扰。
自适应迭代轮数
根据协议 TVL 和漏洞模式复杂度动态决定跑几轮，高 TVL 复杂合约多跑、简单合约少跑，不再硬编码 5 轮。
跨合约调用链追踪
抽取合约所有外部调用，递归拉取目标合约源码（深度 ≤ 2），构建调用图注入分析上下文，覆盖跨协议价格依赖漏洞。
需要手动做的事：装 Slither + Foundry 环境、为 21 个 pattern 标复杂度权重、从 DeFiHackLabs 挑选 5–10 个正样本、选 5–6 个已知安全的合约作为负样本、把 history.json 里 33 个案例标注到具体 pattern ID。
