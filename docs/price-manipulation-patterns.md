# 价格操纵攻击类型体系

> 本文档定义了系统聚焦的 21 种价格操纵漏洞模式（6 大类），由 `@docs/price-manipulation-patterns.md` 引用加载。所有分析 Agent 必须覆盖以下模式。

---

## 类别 1: Oracle Dependency Flaws（价格预言机依赖缺陷）

### OD-01 — Spot Price Directly Used as Pricing Basis（现货价格直接作为定价依据）[Critical]

**攻击原理**：函数直接使用 pair.getReserves() 或 balanceOf 的返回值进行资产定价，未应用时间加权平均或等价保护，攻击者可通过闪电贷在单笔交易中扭曲价格。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 直接读取 pair.reserve 计算价格 | 高 | 未使用聚合价格源 |
| 使用 balanceOf 结果直接定价 | 高 | 余额可被闪电贷瞬间改变 |
| 未使用 TWAP 或多源价格验证 | 高 | 单一价格源依赖 |
| 价格偏差未设置阈值检查 | 高 | 无异常价格检测 |

**防御策略**：
- **即时**：使用 TWAP 而非 spot price；增加价格偏差检查
- **短期**：集成多个预言机源；实施价格波动限制
- **长期**：使用 Chainlink 等去中心化预言机

### OD-02 — Short-Window / Manipulatable TWAP（短窗口/可操控 TWAP）[High]

**攻击原理**：使用了 AMM 的 TWAP 机制，但采样窗口过短（如仅 1-2 个区块），攻击者可通过闪电贷或连续交易轻易扭曲。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| TWAP 周期小于 30 分钟 | 高 | 窗口过短易被操纵 |
| 仅使用 2 个区块数据 | 高 | 样本量不足 |
| 低流动性池作为 TWAP 数据源 | 高 | 操纵成本低 |
| 可被选择性更新 | 高 | 更新机制缺陷 |

**防御策略**：
- **即时**：增加 TWAP 窗口长度；实施价格偏差限制
- **短期**：集成外部价格源验证；监控异常 TWAP 变动
- **长期**：使用 Chainlink 价格聚合器

### OD-03 — Centralized / Unverified Price Feed（中心化/未验证的喂价）[Critical]

**攻击原理**：仅依赖单一链下 API 喂价，或虽有多源聚合但未对价格偏差进行异常值剔除；或单一管理员可更新链上价格。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 单一链下 API 喂价 | 高 | 无去中心化验证 |
| 多源聚合无偏差过滤 | 高 | 异常值未被剔除 |
| 单一管理员可更新价格 | 高 | 中心化控制风险 |
| 无时间锁更新机制 | 高 | 即时恶意更新 |

**防御策略**：
- **即时**：添加多签验证；引入时间锁
- **短期**：去中心化喂价聚合；偏差阈值过滤
- **长期**：采用 Chainlink 去中心化预言机网络

### OD-04 — Stale Oracle Data（预言机数据未验证时效性）[High]

**攻击原理**：合约未检查 updatedAt、roundId 或类似字段，可能使用陈旧、已被操纵的历史价格。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 未检查 updatedAt | 高 | 允许使用过期价格 |
| 未检查 roundId | 高 | 可能使用历史轮次数据 |
| 无价格新鲜度验证 | 高 | 无时效性检查 |
| 可接受任意旧的观察值 | 中 | 回退到旧数据 |

**防御策略**：
- **即时**：添加 updatedAt 检查；设置最大数据时效
- **短期**：实现 roundId 递增验证；添加心跳检测
- **长期**：集成 Chainlink 带时间戳的最新数据接口

### OD-05 — Oracle Update Heartbeat / Delay Tolerance Missing（预言机更新心跳/延迟容忍缺失）[High]

**攻击原理**：合约依赖 Chainlink 等预言机的 latestRoundData()，但未验证 updatedAt 是否在合理时间范围内（如未检查 block.timestamp - updatedAt > 1 小时），允许在预言机停止更新时使用过期价格。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 未检查 updatedAt 时效性 | 高 | 未比较 block.timestamp - updatedAt |
| 无心跳超时回退机制 | 高 | 预言机停更时无保护措施 |
| 接受任意陈旧价格 | 高 | 无最大延迟容忍度 |
| 缺乏价格更新频率监控 | 中 | 无法检测到预言机异常 |

**防御策略**：
- **即时**：添加 block.timestamp - updatedAt 检查；设置最大延迟阈值（如 1 小时）
- **短期**：实现多预言机心跳交叉验证；添加价格更新监控
- **长期**：部署链下监控机器人，确保预言机及时更新

## 类别 2: Liquidity & Reserve Manipulability（流动性与储备可操纵性）

### LR-01 — Mint/Burn Price Depends on Instant Reserves（铸造/销毁定价依赖瞬时储备）[Critical]

**攻击原理**：mint 或 burn 函数中的份额/代币数量计算直接使用当前池子储备量 reserve0, reserve1，无滑点保护或延迟机制。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| mint/burn 直接使用 reserve | 高 | 储备量可被单笔交易操纵 |
| 无滑点保护 | 高 | 闪电贷可实现极端滑点 |
| 无延迟机制 | 高 | 瞬时状态被直接用于计算 |
| 单边流动性操作无保护 | 高 | 非对称操作可扭曲价格 |

**防御策略**：
- **即时**：添加最小流动性要求；实施铸币滑点保护
- **短期**：引入时间加权储备量；限制大额操作
- **长期**：重构储备量独立的价格发现机制

### LR-02 — Collateral/Margin Ratio Uses Manipulatable Price（抵押率/保证金率计算基于可操纵价格）[Critical]

**攻击原理**：借贷或杠杆协议中 collateralFactor、healthFactor 或保证金要求使用易被闪电贷操纵的价格源（如 AMM 现货价），导致不当清算。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 抵押品估值使用现货价格 | 高 | 可被闪电贷瞬时操纵 |
| healthFactor 基于可操纵价格 | 高 | 触发不公平清算 |
| 使用 AMM spot price 作为保证金计算依据 | 高 | 典型操纵路径 |
| 无价格偏差保护 | 高 | 极端价格直接生效 |

**防御策略**：
- **立即**：使用 TWAP 或 Chainlink 进行抵押品估值
- **短期**：设置价格偏差阈值；延迟清算执行
- **长期**：采用多源价格聚合和异常检测

### LR-03 — TVL/Volume-Driven Fee or Reward Distribution（TVL/交易量驱动费用分配）[High]

**攻击原理**：协议奖励、费用分配或治理权重依赖 totalSupply、totalValueLocked 等可瞬时改变的状态变量。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 奖励基于瞬时 TVL | 高 | 可在单笔交易内改变 |
| 费用分配基于当前 supply | 高 | 可被闪电贷影响 |
| 治理权重基于可改变状态 | 高 | 治理攻击风险 |

**防御策略**：
- **即时**：使用时间加权 TVL；设置分配延迟
- **短期**：实现快照机制；限制单次分配量
- **长期**：引入链下验证的分配方案

## 类别 3: Transaction Ordering & Timing（交易排序与时序依赖）

### TO-01 — Missing Deadline / Protection Window（缺少交易截止时间/保护窗口）[High]

**攻击原理**：交易函数（swap, deposit, withdraw）缺少 deadline 参数或设置过长，或可预测的周期性操作缺少保护窗口，允许矿工/MEV 延迟执行。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| swap 函数无 deadline | 高 | 交易可被无限延迟 |
| deadline 设置过长 | 高 | >30分钟的期限易被利用 |
| 周期性操作无保护窗口 | 高 | 可预测操作可被抢跑 |
| 缺少交易时效性检查 | 高 | 旧交易可被延迟执行 |

**防御策略**：
- **即时**：添加 deadline 参数（建议5-10分钟）
- **短期**：集成 MEV 保护；使用私有交易池
- **长期**：部署公平排序机制

### TO-02 — No Slippage Protection / Excessive Tolerance（无滑点保护/容忍度过大）[High]

**攻击原理**：amountOutMin 设为 0 或由用户任意设置，合约未强制最大滑点限制。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| amountOutMin 可为 0 | 高 | 无最小输出保护 |
| 合约不强制最大滑点 | 高 | 用户可能设置极端值 |
| 滑点参数可被抢跑修改 | 高 | MEV 风险 |
| 无合约层面滑点上限 | 高 | 完全依赖用户输入 |

**防御策略**：
- **即时**：合约强制最大滑点；添加最小输出检查
- **短期**：实施动态滑点保护；基于 TWAP 计算基准
- **长期**：集成 MEV 保护方案

### TO-03 — State Changed Multiple Times in One Transaction (Reentrancy-Type)（单交易内状态可被多次改变-重入型）[Critical]

**攻击原理**：价格或储备相关状态更新发生在外部调用（如 swap callback）之后且未使用重入锁，允许通过重入在单笔交易中反复扭曲价格。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 状态更新在外部调用后 | 高 | 经典重入模式 |
| 无重入锁保护 | 高 | 缺乏基本防护 |
| 价格关键变量在外调后更新 | 高 | 可被反复修改 |
| 使用 unchecked 区块 | 中 | Solidity 0.8+ gas 优化隐患 |

**防御策略**：
- **即时**：添加 ReentrancyGuard；遵循 Check-Effects-Interactions
- **短期**：将所有状态更新移至外部调用之前
- **长期**：使用 Pull-over-Push 支付模式

## 类别 4: Access Control & Privilege Risks（访问控制与特权风险）

### AC-01 — Oracle Address Update Without Timelock/Multi-sig（预言机地址可单方面更新）[Critical]

**攻击原理**：更新预言机地址的函数仅由 owner 调用，缺少时间锁或多签验证。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| owner 直接更新预言机地址 | 高 | 单点控制 |
| 无时间锁 | 高 | 即时生效 |
| 无多签要求 | 高 | 无多方验证 |
| 无事件通知机制 | 中 | 隐藏更新 |

**防御策略**：
- **即时**：添加 timelock（最少24小时）；要求多签
- **短期**：实施两步迁移流程；添加事件监控
- **长期**：去中心化预言机治理

### AC-02 — Economic Parameters Adjustable by Privileged Role（协议经济参数可特权调整）[High]

**攻击原理**：手续费率、利率、抵押率等关键参数可由单一管理员账户无时间锁地任意修改。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 关键参数可由单个地址修改 | 高 | 中心化风险 |
| 无时间锁 | 高 | 即时生效 |
| 修改无上限限制 | 高 | 可极端调整参数 |

**防御策略**：
- **即时**：添加参数修改的时间锁；设置最大变化幅度
- **短期**：实施多签治理；添加参数变更事件
- **长期**：完全去中心化治理

### AC-03 — Concentrated Token Mint/Burn Privileges（代币铸造/销毁权限集中）[Critical]

**攻击原理**：拥有 mint/burn 权限的地址可无限增发或销毁代币，直接影响价格和供应量。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 单一地址拥有 mint 权限 | 高 | 可无限增发 |
| 单一地址拥有 burn 权限 | 高 | 可销毁他人代币 |
| 无铸造上限 | 高 | 供应量可被无限改变 |
| 无时间锁限制 | 高 | 即时执行 |

**防御策略**：
- **即时**：添加 mint cap；移除 burn 权限或限制为己有代币
- **短期**：实施多签 mint 流程；添加上限和时间锁
- **长期**：完全移除特权 mint/burn 功能

## 类别 5: Calculation Logic Bugs（计算逻辑缺陷）

### CL-01 — Exploitable Rounding Direction（舍入方向可被利用）[Medium]

**攻击原理**：除法或取模运算中未正确处理余数，攻击者可通过反复小规模操作提取价值。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 整数除法截断余数 | 高 | Solidity 向下取整 |
| 重复操作可累积收益 | 高 | 精度套利 |
| 未使用高精度数学库 | 中 | 基本 math 操作 |

**防御策略**：
- **即时**：使用 SafeMath 或 PRBMath 库
- **短期**：添加最小操作量要求；实施精度检查
- **长期**：形式化验证关键计算

### CL-02 — Decimal Mismatch in Price Calculation（Decimal 不匹配）[High]

**攻击原理**：价格或汇率计算中混用了不同小数位数的代币（如 USDC 6位与 ETH 18位），导致计算偏差。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 不同 decimals 混用计算 | 高 | 6位 vs 18位偏差 |
| 无规范化处理 | 高 | 直接使用原始值 |
| 缩放因子硬编码 | 中 | 假设所有代币18位 |

**防御策略**：
- **即时**：使用 token.decimals() 动态获取；规范化所有输入
- **短期**：添加 decimals 验证；编写 normaliseAmount 工具函数
- **长期**：使用通用数学库处理多精度代币

### CL-03 — AMM Curve / Parameter Misconfiguration（AMM 曲线/参数设计不当）[High]

**攻击原理**：自定义曲线参数允许极端交易时出现不合理滑点；或标准恒定乘积 AMM 在极端交易量下未设保护。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 自定义曲线无极端值保护 | 高 | 极端参数产生不合理输出 |
| 恒定乘积 AMM 无边界检查 | 高 | 极端交易量导致价格偏离 |
| 缺少交易量限制 | 高 | 可一次性大幅扭曲价格 |
| 曲线参数可动态调整 | 中 | 参数本身可被优化利用 |

**防御策略**：
- **即时**：形式化验证 AMM 曲线；添加边界检查
- **短期**：限制极端参数值；实施暂停机制
- **长期**：使用经过审计的 AMM 模板

## 类别 6: Composability Risks（可组合性风险）

### CR-01 — Reliance on External Protocol / Bridge as Sole Price Source（依赖外部协议/跨链桥作为唯一定价源）[Critical]

**攻击原理**：核心逻辑（清算、借贷）直接调用外部 DEX 或跨链桥的 getAmountOut，且无备用价格源或断路器。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 直接调用外部 getAmountOut | 高 | 单一故障点 |
| 无备用价格源 | 高 | 无冗余 |
| 无断路器 | 高 | 即使发现异常也无法中断 |
| 跨链桥作为唯一价格源 | 高 | 桥接价格可被操纵 |

**防御策略**：
- **即时**：添加断路器；实现备用价格源
- **短期**：多协议价格聚合；偏差阈值检查
- **长期**：内部价格发现机制；减少外部依赖

### CR-02 — Unverified Assumption of External LP Token Value（对外部 LP Token 的价值假设未验证）[High]

**攻击原理**：协议接受用户存入的 LP token 并直接按"当前价值"计算抵押物，未验证其底层组成是否已被操纵。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| LP token 作为抵押物 | 高 | 价值取决于底层组成 |
| 未验证底层 token 比例 | 高 | 组成可被操纵 |
| 直接使用 LP token 报价 | 高 | 报价可能失实 |

**防御策略**：
- **即时**：验证 LP token 底层组成；使用 TWAP 估值
- **短期**：实施抵押物折扣率；限制 LP token 类型
- **长期**：独立定价预言机方案

### CR-03 — Cross-Protocol Call Without Return/Consistency Check（跨协议调用未检查返回值/状态一致性）[High]

**攻击原理**：调用外部合约进行 swap/liquidate 等操作后未验证返回值，或未处理被调用合约回滚可能导致的不一致状态。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 未检查外部调用返回值 | 高 | 调用结果未验证 |
| 未处理外部合约回滚 | 高 | 状态不一致风险 |
| 无一致性验证 | 高 | 前后状态可能矛盾 |

**防御策略**：
- **即时**：检查所有外部调用返回值；处理回滚
- **短期**：添加调用后状态一致性验证
- **长期**：使用标准化的跨协议交互接口

### CR-04 — Unverified Cross-Protocol Price Dependency（未验证的跨协议价格依赖）[High]

**攻击原理**：协议 B 的清算或定价逻辑依赖于协议 A 的流动性或价格，且未对价格偏差进行验证。攻击者可操纵协议 A 的储备间接扭曲协议 B 的价格，形成跨协议级联攻击。

**检测指标**：
| 指标 | 权重 | 说明 |
|------|------|------|
| 定价函数调用了外部 AMM 的 getReserves | 高 | 外部储备可被操纵 |
| 无跨协议价格偏差检查 | 高 | 未验证来源价格是否合理 |
| 未使用 TWAP 或链下预言机交叉验证 | 高 | 单一外部路径依赖 |
| 依赖链深度 ≥ 2 的外部调用链 | 高 | 间接价格依赖风险 |

**防御策略**：
- **即时**：添加价格偏差阈值检查；实现断路器机制
- **短期**：使用多源价格聚合和交叉验证
- **长期**：减少对外部协议的定价依赖，建立独立的价格发现机制

## 交叉类别关系

攻击模式之间常存在组合利用关系：

```
LR-01 (Instant Reserve) ──enables──→ OD-01 (Spot Price)
LR-01 (Instant Reserve) ──enables──→ LR-03 (TVL-Driven Fees)
OD-01 (Spot Price) ──amplifies──→ LR-02 (Collateral Ratio)
```

### 常见组合攻击链

1. **经典闪电贷到预言机链**：LR-01 → OD-01 → LR-03（闪电贷储备操纵 → 现货价格扭曲 → 费用/奖励操纵）
2. **预言机喂价到清算链**：OD-03 → LR-02（中心化喂价被篡改 → 触发不公平清算）
3. **预言机过期级联链**：OD-04 → OD-05（陈旧预言机数据 → 心跳缺失导致持续使用过期价格）
4. **MEV 夹击链**：TO-01 → TO-02（无截止时间 + 无滑点保护 → 三明治攻击）
5. **跨协议级联链**：CR-01 → CR-03（单一外部价格源被操纵 → 跨协议状态不一致）
6. **跨协议间接价格操纵链**：CR-04 → CR-01（外部协议价格被操纵 → 间接传导至目标协议）
7. **特权滥用级联链**：AC-01 → AC-02 → OD-03（预言机地址被修改 → 参数被调整 → 喂价被污染）
