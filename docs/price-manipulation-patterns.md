# 价格操纵攻击类型体系

> 本文档定义了系统聚焦的 8 种价格操纵攻击模式，由 `@docs/price-manipulation-patterns.md` 引用加载。所有分析 Agent 必须覆盖以下模式。

---

## VP001 — Oracle Manipulation（预言机操纵）

### 攻击原理
攻击者通过操纵预言机价格源，使智能合约读取到虚假价格信息。核心问题是合约依赖可被外部影响的单一价格源，且缺乏价格偏差检查和时效性验证。

### 典型场景
- 借贷协议清算：操纵预言机触发不公正清算
- DEX 交易执行：通过虚假价格获取套利空间
- 衍生品结算：影响标记价格导致不当结算

### 检测指标
| 指标 | 权重 | 说明 |
|------|------|------|
| 直接读取 pair.reserve 计算价格 | 高 | 未使用聚合价格源 |
| 使用 block.timestamp 作为唯一时间戳 | 中 | 缺乏时间窗口保护 |
| 未使用 TWAP 或多源价格验证 | 高 | 单一价格源依赖 |
| 依赖单一价格源 | 高 | 缺乏冗余验证 |
| 低流动性池作为价格预言机 | 高 | 易被操纵 |
| 价格偏差未设置阈值检查 | 高 | 无异常价格检测 |
| fallback 预言机使用 DEX 即时价格 | 中 | 回退机制不安全 |

### 防御策略
- **即时**：使用 TWAP 而非 spot price；增加价格偏差检查
- **短期**：集成多个预言机源；实施价格波动限制
- **长期**：使用 Chainlink 等去中心化预言机；部署预言机守护者监控

### 优先检测协议
DEX, AMM, Perp, Lending

---

## VP002 — Flash Loan Attack（闪电贷攻击）

### 攻击原理
攻击者在单笔交易内借用大量无抵押资金，利用这些资金操纵市场状态，在归还闪电贷前完成获利操作。核心条件是合约在单笔交易中接受外部资金影响，且缺乏跨区块验证。

### 典型场景
- 治理投票：闪电贷获取代币影响投票结果
- 价格操纵：利用大量资金瞬间扭曲价格
- 套利攻击：跨协议价格差异利用

### 检测指标
| 指标 | 权重 | 说明 |
|------|------|------|
| 无多区块确认机制 | 高 | 单交易可完成攻击循环 |
| 依赖可被闪电贷影响的参数 | 高 | 关键参数无时间锁 |
| 缺少交易间隔检查 | 中 | 无防重入时间保护 |
| 同一交易内多次调用敏感函数 | 高 | 典型攻击模式 |
| mint/burn 价格依赖可操控的现货价格 | 高 | 价格源可被操纵 |
| 单笔交易内完成借款-操纵-获利循环 | 高 | 完整攻击路径 |

### 防御策略
- **即时**：增加时间锁；限制单笔交易中的累积影响
- **短期**：使用链上历史价格平均；实施交易量限制
- **长期**：部署 MEV 保护机制；使用 Commit-Reveal 方案

### 优先检测协议
DEX, AMM, Perp, Lending, Yield Aggregator

---

## VP003 — Reserve Manipulation（储备金操纵）

### 攻击原理
攻击者通过直接修改或谎报合约储备金数据获利。典型手段包括利用 `skim()`/`sync()` 函数、通过转账操纵池余额、或利用储备金计算中的逻辑缺陷。

### 典型场景
- 跨链桥：操纵桥接储备金证明
- 稳定币：虚假储备金支撑超发

### 检测指标
| 指标 | 权重 | 说明 |
|------|------|------|
| 直接使用 reserve 计算兑换比例 | 高 | 储备金数据可被操纵 |
| 无储备金变化限制 | 高 | 缺乏变化率检查 |
| 可被大额交易影响计算结果 | 中 | 无交易量限制 |
| 缺少储备金验证 | 高 | 无一致性验证 |
| transfer 路径可操控 pair 余额 | 高 | 直接转账漏洞 |
| skim()/sync() 可被恶意利用 | 高 | 缺乏访问控制 |

### 防御策略
- **即时**：移除直接修改储备金的函数；增加储备金验证
- **短期**：使用预言机获取储备金数据；实施多签控制
- **长期**：完全重构储备金管理逻辑

### 优先检测协议
Lending, Bridge

---

## VP004 — Price Calculation Flaw（价格计算缺陷）

### 攻击原理
价格计算公式中存在数学漏洞，包括精度损失、整数溢出、小数缩放错误、地板除法问题等。攻击者精心构造输入参数利用这些计算缺陷获取不当利益。

### 典型场景
- AMM 交易：利用精度损失获取超额代币
- 滑点计算：地板除法导致滑点保护失效

### 检测指标
| 指标 | 权重 | 说明 |
|------|------|------|
| 使用整数除法计算价格 | 高 | 可能导致精度损失 |
| 未使用高精度数学库 | 中 | 缺乏安全计算保障 |
| 缺少边界检查 | 高 | 无极值保护 |
| 除法顺序可能导致精度损失 | 高 | 先除后乘问题 |
| 小数缩放重复乘以 1e18 | 中 | 精度累积误差 |
| 地板除法可被操控到零 | 高 | 零值安全风险 |
| burn 机制不当影响价格计算 | 中 | 计算逻辑缺陷 |

### 防御策略
- **即时**：使用安全的数学库；增加精度检查
- **短期**：实施价格偏差限制；增加测试覆盖
- **长期**：形式化验证关键计算逻辑

### 优先检测协议
Perp, Lending

---

## VP005 — Liquidity Pool Manipulation（流动性池操纵）

### 攻击原理
攻击者操纵流动性池状态导致价格异常。典型手段包括利用 LP 代币铸造逻辑缺陷、添加/移除流动性操作不当、访问控制缺失等。Uniswap V4 Hook 的访问控制问题也属于此类。

### 典型场景
- NFT 市场：操纵 NFT 流动性池定价
- AMM：利用流动性操作缺陷

### 检测指标
| 指标 | 权重 | 说明 |
|------|------|------|
| 直接操作 LP 代币 | 高 | 缺乏验证 |
| 未验证流动性池状态 | 高 | 无状态一致性检查 |
| 添加/移除流动性逻辑缺陷 | 高 | 操作顺序可被利用 |
| 无常损失处理不当 | 中 | 经济模型缺陷 |
| LP 移除函数可被滥用 | 高 | 缺乏访问控制 |
| Uniswap V4 Hook 缺少访问控制 | 高 | 新型攻击向量 |
| 奖励分配逻辑可被重复领取 | 高 | 重入攻击风险 |

### 防御策略
- **即时**：设置最小流动性要求；增加价格影响警告
- **短期**：实施动态滑点保护；限制大额流动性移除
- **长期**：使用分级流动性机制

### 优先检测协议
AMM, DEX

---

## VP006 — Slippage Control Bypass（滑点保护绕过）

### 攻击原理
滑点保护机制可被绕过或操控，攻击者通过 MEV 抢跑在用户交易前操纵价格，或利用 swap 参数被恶意构造执行未授权的 transferFrom。

### 典型场景
- DEX 交易：三明治攻击利用滑点保护不足
- 路由器合约：已获批后被利用执行恶意转账

### 检测指标
| 指标 | 权重 | 说明 |
|------|------|------|
| 用户可设置过大滑点 | 中 | 缺乏上限限制 |
| 滑点计算基准可被操纵 | 高 | 基准价格不可靠 |
| 无滑点上限限制 | 高 | 无保护机制 |
| 滑点参数可被抢跑修改 | 高 | MEV 风险 |
| swap 参数可被恶意构造执行 transferFrom | 高 | 参数注入漏洞 |
| 路由器合约获批后被利用 | 中 | 授权滥用 |

### 防御策略
- **即时**：增加最小滑点限制；实施 TWAP
- **短期**：集成 MEV 保护；使用私有交易池
- **长期**：部署公平排序机制

### 优先检测协议
AMM, DEX, Perp

---

## VP007 — TWAP Manipulation（TWAP 操纵）

### 攻击原理
TWAP 实现存在漏洞，攻击者通过多个区块的交易操纵时间加权平均价格。典型问题包括窗口过短、仅使用2个区块数据、低流动性池作为 TWAP 数据源等。

### 典型场景
- 使用 TWAP 作为价格源的协议（借贷、衍生品）
- 流动性衰减导致预言机可被操控

### 检测指标
| 指标 | 权重 | 说明 |
|------|------|------|
| TWAP 周期小于 30 分钟 | 高 | 窗口过短易被操纵 |
| 仅使用 2 个区块数据 | 高 | 样本量不足 |
| 可被选择性更新 | 高 | 更新机制缺陷 |
| 可被提前交易操纵 | 中 | MEV 风险 |
| 低流动性池作为 TWAP 数据源 | 高 | 操纵成本低 |
| 流动性衰减导致预言机可被操控 | 中 | 动态风险 |

### 防御策略
- **即时**：增加 TWAP 窗口长度；实施价格偏差限制
- **短期**：集成外部价格源验证；监控异常 TWAP 变动
- **长期**：使用 Chainlink 价格聚合器

### 优先检测协议
AMM, DEX

---

## VP008 — AMM Exploitation（AMM 利用）

### 攻击原理
利用 AMM 数学不变量或边界条件进行攻击。典型手段包括重入漏洞操纵全局平均价格、三明治攻击、精度损失利用、批量 swap 操控池状态和内部余额等。

### 典型场景
- 恒定乘积 AMM（Uniswap V2/V3 风格）
- 自定义 AMM 实现

### 检测指标
| 指标 | 权重 | 说明 |
|------|------|------|
| 依赖 AMM 恒定乘积公式 | 中 | 基础数学模型 |
| 未考虑三明治攻击 | 高 | 缺乏排序保护 |
| 交易顺序可被操纵 | 高 | MEV 风险 |
| 缺少私有交易池支持 | 中 | 无隐私保护 |
| 重入可操纵全局平均价格 | 高 | 重入漏洞 |
| 批量 swap 可操控池状态和内部余额 | 高 | 状态一致性风险 |

### 防御策略
- **即时**：形式化验证 AMM 合约；增加边界检查
- **短期**：限制极端参数值；实施暂停机制
- **长期**：使用经过审计的 AMM 模板

### 优先检测协议
AMM, DEX

## 交叉模式关系

攻击模式之间常存在组合利用关系：

```
VP002 (Flash Loan) ──enables──→ VP001 (Oracle Manipulation)
VP002 (Flash Loan) ──enables──→ VP005 (Liquidity Pool Manipulation)
VP001 (Oracle Manipulation) ──amplifies──→ VP007 (TWAP Manipulation)
VP005 (Liquidity Pool) ──enables──→ VP008 (AMM Exploitation)
VP003 (Reserve) ──amplifies──→ VP004 (Price Calculation Flaw)
VP006 (Slippage Bypass) ──requires──→ VP008 (AMM Exploitation)
```

### 常见组合攻击链

1. **经典闪电贷攻击链**：VP002 → VP001 → VP005（闪电贷 → 操纵预言机 → 操纵流动性池）
2. **TWAP 攻击链**：VP002 → VP007 → VP001（闪电贷 → 操纵 TWAP → 预言机价格偏离）
3. **滑点攻击链**：VP006 → VP008 → VP005（滑点绕过 → AMM 利用 → 流动性操纵）
4. **储备金攻击链**：VP003 → VP004 → VP001（储备金操纵 → 计算缺陷 → 预言机异常）
